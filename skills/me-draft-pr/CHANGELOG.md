# Changelog

## 2026-11-10

### Consolidate PR writing guidance

Keep PR body conventions in the drafting skill so agents use one source for formatting and evidence. GitHub pull request and issue URLs remain inline and unlabelled so GitHub can render its short references.

### Describe the change without commands

Make the present-tense instruction explicit so the opening describes the PR instead of asking the reviewer to perform the change.

## 2026-11-06

### Explain what changed

Describe the change in behavior or workflow, not just the resulting code. Include the prior behavior when it makes the change clear. Present tense alone does not establish what changed.

### Lead with the change

Make the opening identify the change and new behavior. A statement of capability can leave it unclear whether the behavior already existed.

## 2026-11-04

### Preserve GitHub attachments when publishing

Preserve draft attachments when publishing. A chart was omitted from an issue even though GitHub CLI supports [attachments](https://cli.github.com/manual/gh_issue_edit).

## 2026-11-03

### Describe the change

Write PR bodies in present tense rather than as instructions, which can read like a request instead of a description of the change.

## 2026-11-02

### Follow configured draft conventions

Use the user's existing draft destination instead of asking for a folder already configured elsewhere.

## 2026-10-29

### Use the conversation and current changes

A PR draft can follow implementation without restating the change. Use the conversation to identify the scope, inspect the relevant diff, and honor a request to draft in chat.


## 2026-10-26

### Preserve existing PR content

Require targeted edits to a freshly read PR body. Replacing a broad section can remove images or text added by someone else.
