# Changelog

## 2026-11-12

### Rewrite the whole outcome when updating

Replace the complete workstream bullet from current facts and read the result before saving. Phrase-level status updates can retain obsolete details and turn a short outcome into an activity log. Keep supporting evidence reachable through linked material.

### Record results rather than preparation

Require a concrete result before adding an outcome. Keep preliminary research and local drafts in work notes or the pending queue, while preserving meaningful results from unfinished tasks.

### Keep daily outcomes skimmable

Rewrite updates around the current result and remaining work, with supporting detail in linked material. Preserve useful links when shortening or combining outcomes.

### Keep outcomes and queues optional

Describe daily outcomes for users who enable them and use supplied queue locations and history rules. Preserve source checks, deduplication, and history without making note access enable extra workflows.

## 2026-11-04

### Make review follow-ups actionable

Put the request thread and who is waiting first, and name the action needed. Keep other response locations visible, including cross-posted requests, while separating supporting evidence and past status updates into context. This makes the request and where to respond easier to find.

## 2026-11-03

### Consolidate repeated review pings

Match the underlying review across different message URLs and channels. Keep one queue entry with its existing next action and priority, plus dated source links and the people waiting on each follow-up. A repeated ping for an already queued PR should refresh its follow-up history rather than create another task. This preserves both logical deduplication and a record of where to respond.

## 2026-11-02

### Edit Obsidian configuration headlessly

Use the vault's .obsidian files for settings and hotkeys, preserve unrelated configuration, and report reload requirements without taking over the app. The user found computer-use setup disruptive and explicitly requested direct file edits. UI interaction requires an explicit request.

### Keep reviews in a persistent queue

Use a mutable root-level Review Queue.md for pending reviews and follow-ups, with outcomes preserved in dated daily notes. This keeps reviews visible after missed reminders without losing daily history. Reuse the existing queue and retain unverified entries until checked.

### Document daily note plugins

Recommend Periodic Notes and Folder notes for creating and navigating daily notes. Calendar is optional. The file-based workflow remains usable without them.

### Define the daily work structure

Keep the daily folder and shared numbered sequence in the skill, so recent work is easy to find. Count files and folders by their highest prefix to avoid reusing a number after a deletion. Sidemark is optional and used only when requested.

### Centralize draft numbering

The vault workflow owns the shared daily counter for PR and issue drafts. Both drafting skills previously duplicated it.

### Use configured vault conventions

Keep the workflow reusable while using the user's configured vault location, note layout, and link format. The personal configuration remains available outside the skill.

## 2026-10-09

Require a link even in the final reply. A previous agent gave only a path after editing a note, making it harder to open.
