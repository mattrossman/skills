# Contributing

## Maintaining skills

Each skill lives in `skills/<name>/` and has a `SKILL.md` with its instructions and a `CHANGELOG.md` that records dated changes and the problems they address.

Before editing a skill, read its changelog and check that your changes still address the recorded problems.

For each substantive change, add an entry with a date heading (`## YYYY-MM-DD`) and a descriptive change heading (`### ...`). Explain what changed, the problem that prompted it, and the behavior to preserve. Use a concrete example when it clarifies the behavior. Put newest dates first and group changes made on the same date under that date heading. Correct old entries with a new entry. Keep personal and machine-specific details out of this repository.
